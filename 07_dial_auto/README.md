# 07_dial_auto 学習なしで圧力計を読む(試作)

計器ごとの学習をせず、写真から「目盛りの角度」「目盛りの数字」「針の角度」を求めて値を計算する試作。LLM は使わない。
数字の読み取りに EasyOCR(学習済みの文字認識、PC で動く)を使う。

使い方: `pip install easyocr` → `python dial_auto.py 写真…`(初回は EasyOCR のモデルを自動でダウンロード)

## 手順
1. 黒縁の内側の楕円(05_ml/kuro.py)で仮に正面化
2. 目盛りの外側の細い円弧の点を探し、楕円を当てはめ直して正面化(縁は文字盤より手前にあり、中心がずれるため)
3. 円弧のすぐ外側・内側の帯で目盛り線を探し、等間隔の並びがいちばん長く続く範囲 → 目盛りの両端の角度・本数・間隔
4. EasyOCR で数字を読み(1文字の「0」「1」はまず読めない)、角度と値の関係を外れ値に強い当てはめで求める
   → 最小値、1目盛りの値(1,2,5×10^k に丸め)× 本数で最大値
5. 針: 赤チャンネル(赤い置針が白くなる)の極座標で、各リングの暗さ → 下から30%の値が最大の角度
6. 値 = 最小値 + (針の角度 − 始まりの角度) ÷ 振れ角 × (最大値 − 最小値)

## 結果(2026-11-22、TOKO 0〜1.0MPa)
- 別の計器(針固定 0.87)の iPhone 写真8枚: 0.858〜0.888(すべて ±2%FS 以内)
- 疑似圧力計の測定画像45枚(正面・上下左右30°、0.2/0.5/0.8): 44枚で値、平均絶対誤差 1.46%FS、最大 2.9%FS、±2%FS以内 26/44。
  1枚は数字の当てはめが崩れて範囲が異常(値は出さない扱い)。同じ画像で CNN(net_phone_v1)は平均 0.57%FS
- 誤差の主な原因: 上30°で文字盤下のロゴを目盛り線と取り違え振れ角が290°に(実際は約270°)、右30°で針が −1.5%FS 寄る(軸の位置ずれ・視差)

## 前提・弱点
- 時計回りに増える一様な目盛り。真空計・連成計・非線形の目盛り、2重目盛りは未対応
- 数字が2つ以上読めること。XIAO の 640×480 では数字が小さく、OCR は難しい見込み(未確認)
- 処理時間は未計測(試験のPCでは45枚で数分、大半は EasyOCR)。設置時に1回だけ目盛りを求めて保存し、ふだんは針の角度だけ読む使い方を想定
