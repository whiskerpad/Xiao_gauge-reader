# gauge-reader 開発ログ

アナログ圧力計の針をマイコンのカメラで読み取るプロジェクトの記録。
後で人やAIが読み返して経緯・判断・現状を把握できるように書いている。
新しい作業をしたら末尾の「作業記録」に追記し、「現状」「既知の課題」を更新すること。

---

## 1. 目的と全体方針

- ビルメン(ビル設備管理)ブログの連載テーマ。巡回点検で目視しているアナログ計器を自動で読む
- 手持ちのマイコン/AIカメラ(XIAO ESP32S3 Sense、ESP-EYE、Maix Bit、OAK-D S2)を全部使い、
  従来の画像処理 → 機械学習 までの道のりを記録・発表する
- 進め方(2026-11-13 決定)
  1. 評価装置(疑似メーター+フード+照明制御+PC評価スクリプト)を作る
  2. XIAOの従来手法(画像処理)で「安いカメラの到達点」を出して区切る
  3. 同じ装置で各カメラの真値付き画像を集める
  4. 機械学習はPCで上限を出してから OAK-D → Maix Bit → ESP32-S3 に落とす
  5. 最後にラズパイを収集サーバーとして常時運用
- 評価の点数 = 正解(誤差±2%FS以内)÷ 全試行 × 100。誤読(大きく外れた値)は別集計し、0を必須とする
- **現場で成立すること**を重視(2026-11-14 の議論):
  - フード+自前照明は「装置の一部として現場に持ち込む」ので可
  - 背景差分(針を動かして背景を作る)、真値を使う直線補正は実験室でしか成立しない → 現場向けの方式に置き換える
  - 疑似メーターは現場の代わりではなく、性能を測る試験装置

## 2. ハードウェア構成

| 部位 | 内容 |
|---|---|
| 計器 | 実物の圧力計(TOKO、0〜1.0MPa、振れ角約270°、精度等級1.6級と思われる)の文字盤と化粧カバー。針のおしりに二股の意匠あり。赤い置針(警告目安)が0.8MPaに固定 |
| 疑似針 | 28BYJ-48 + ULN2003、Arduino UNO で駆動。ストッパー押し当てで原点化 |
| カメラ | XIAO ESP32S3 Sense、センサーは **OV3660**(リボンに刻印)。左右反転して写るので hmirror=1 |
| 照明 | 紙の仮フード+LED1点(2026-11-14)。4点LED+3Dプリントフードを計画中 |
| PC | Windows。G:\gauge-reader で作業。司令塔はPC(ラズパイは最終段階) |

UNO配線(現状): D8〜D11 → ULN2003 IN1〜IN4。
照明を4点PWM化する場合は、モーターを D4〜D7 に移し、LEDを D3/D9/D10/D11(31kHz PWM)にする計画。
(理由: UNO標準PWMは490/980Hzで、ローリングシャッターに横縞が出る)

### 取扱注意
- XIAO Sense の基板間コネクタ(本体⇔拡張ボード、拡張ボード⇔カメラ)は抜き差しに弱い。2台中1台は着脱でカメラ不認識(0x105)になり回復せず。もう1台は押し込み直しで回復
- XIAOは書き込み・リセットでUSBが切断されCOM番号が変わる。VS Codeのシリアルモニタで出力が拾えないことがあり、Arduino IDEのシリアルモニタで確認している

### XIAOの読み取り方式(gauge.h)
- 角度プロファイル: 0目盛り−5°〜最大目盛り+5°を0.5°刻み。各角度で半径帯の平均輝度。[1,2,1]/4で平滑化
- 暗さ(%) を求め、最も暗い所の周囲(最大値の半分以上)の重心角度を針とする
- 合否: 暗さ8%以上 かつ snr(針の暗さ ÷ 針の前後6°以外の最大の暗さ)1.5以上。区別できなければ値を出さない
- **単一帯モード**(nb=0): 半径 ri〜ro。背景があれば「画像/背景の比の中央値で露出補正 → 背景に対する暗さ」。背景は針を動かしながら、針の±15°を除いたフレームの平均で作る
- **多帯モード**(nb=2〜3、2026-11-14追加、現場向け): 帯ごとに暗さ → ハイパス(±hpw°の移動中央値を差し引く)→ 全帯の最小値。背景不要
- 露出: 自動露出を止めて固定(露光量・ゲインを設定画面から指定、NVS保存)
- 直線補正: 指示値 = ca × 生値 + cb(NVS保存)

密閉フードは却下(目視点検の妨げ、付属物として不自然)。「カメラモジュールを計器の付属物として付け、

## 5. 既知の課題

0. (2026-11-14) 多帯の失敗は0.7〜1.0MPaに集中。原因は最外帯(100〜112)で針の先が薄い/届かない(右下側)。
   最外帯を90〜100に下げるとPC再現で大幅改善。次の実機測定で確認する
0. (2026-11-14) 誤差に系統的な偏り: 0.2〜0.4で+0.008、0.8〜1.0で−0.016(約2.4%FSの振れ)。
   中心の推定し直し(針の線の交点で(327.8,218.9)と推定)では改善しなかった。
   **疑似メーターの真値自体が未校正**(needle_test.py calib 未実施、ZERO_OFFSET_STEPS=0、fullSteps=公称値、
   28BYJ-48の実ステップ数は約4076で公称4096と0.5%違う)なので、読み取り誤差と疑似針の位置誤差が混ざっている。
   先に疑似針を校正し、印刷目盛りと針を目視で合わせてから再評価する

1. 多帯モードを実機で未検証(ファームは書いたが未コンパイル)。別の測定(ランダム50点)で確認が必要
2. 針が主目盛り線やストッパーに重なる位置(0MPaなど)で暗さが出にくい
3. 針のおしりが内側の帯に入る位置がある(0.95〜1.0MPaで、おしりが0.3〜0.45方向)。多帯の最小値で抑えられる想定
4. 誤差に波形の偏り(0.3付近+0.007、0.8付近−0.007)。中心のずれかカメラの傾き。真値を使わずに中心を補正する方法(複数画像の針の線の交点)を検討
5. 直線補正の係数は古いカメラ位置で求めたもの(ca=1.01321, cb=-0.00397)。現状に合っていない。現場では使えない方式
6. 照明4点化、3Dプリントフード(LEDは文字盤側の端、中心軸から計器半径×(1+LED〜ガラス距離/カメラ〜ガラス距離)以上離す。拡散板はLEDから10〜20mm)
7. 蒸気計の振動対策(ハイパス幅を針のぶれ幅より大きくする必要)

### 機械学習版(XIAO 極座標CNN)の課題(2026-11-25 時点)
- **カメラ位置**: 学習時の位置から大きく動かすと読めない(位置合わせは平行移動 ±48px だけ、拡大縮小・斜めは不可)。
  対策として射影変換の補正(/hom、hom_check.py)を入れた。手でカメラを元の位置に戻すのは自由度6つが連動して現実的でない
- **0.9〜1.0MPa で自信が下がる**(補正後、ブラケット変更後の位置・斜め約20°)。0〜0.8MPa は自信0.94〜0.99。
  0.9〜1.0 は0.4〜0.8 で未取得になる(誤読は出ていない)。置針(0.8付近)と針・文字盤の見かけの位置関係が斜めで変わること、
  窓の光の変化が候補。対策案: 今の位置で300位置ほど集め直し、補正後の画像で追加学習(案B、未実施)
- **補正後の読み取りが遅い**: /nn?n=3 で約7秒(1枚の推論1.5秒+変換)。定期読み取り5秒間隔に間に合わない。補正なしとの比較は未測定
- **正解値の精度**: 疑似針(28BYJ-48)のバックラッシュで、上下どちらから近づけたかで0.2〜0.9%FS違う。0.3で+1.6%、0.8で−1%前後の偏りもある。
  1〜2%FS より細かい評価には NEMA17+エンコーダー等で正解を測る必要がある
- **針の軸をクリック点に使わない**: 軸のキャップは文字盤から浮いているので、斜めでは文字盤の面からずれて見え、射影変換を歪める
  (軸込みで conf 0.69 → 目盛り6点だけで 0.80〜0.91)
- 基準画像(reg_ref.npy)の軸のクリック位置(306,216)と学習時の軸 CX,CY(295.7,219.6)が約10px違う。基準画像は300枚の平均で針がぼけているため

## 6. 失敗から得た知見(要点)

- 自動露出は撮影ごとに明るさが揺れる → 固定必須
- 背景を「最大値」で作るとノイズ・白飛び側に偏る → 平均+針周辺除外に変更
- 白飛び(255張り付き)では比率補正が成り立たない。暗すぎ(輝度60台)でも針のコントラストが不足
- 外光・モニターの映り込みで幅30〜44°の暗い領域が時々出る → フードで解消。ハイパスでも抑えられる
- 走査帯に数字・目盛り線・針のおしりが入ると誤読する。帯の位置が最重要
- 設定変更で背景が自動削除されるのを忘れて測定する事故が2回 → run_eval.py に事前チェックを追加
- 計算時間は1枚約8ms。ESP32の計算能力はボトルネックではない。問題は画質と撮影環境

## 8. AIへの引き継ぎメモ

- ユーザーは機械的な回答を好み、意見・レビューだけを求めたときは許可なくコードを変更しないこと
- ファームはクラウド側でコンパイル確認できていない(PlatformIO未導入)。ビルドエラーはユーザーが貼る
- 測定結果の確認依頼が来たら dataset/xiao_s3 の最新フォルダの xiao_config.json(設定・背景/モード)、summary.txt、result.csv を読む。images/ の profile.json に角度ごとの輝度・暗さがある
- 設定変更で背景が消える、露出の「適用」忘れ、「読み取り」を押さずに古いグラフを見る、などの手順ミスが起きやすい。まず設定値を確認する
- 保存画像はJPEG。offline_eval.py で方式を比較できるが、同じ画像で調整すると過学習になる(マーカーモード未対応)
- ファームの構文チェックは、クラウド側でArduino/ESP32のスタブヘッダを作って g++ -fsyntax-only で行った(PlatformIOのレジストリに接続できないため)
- device_commit_files は同じ stagedPath を使い回すと古い内容を書くことがある → 版ごとに新しいフォルダに置き、書き込み後に md5 を確認する
- XIAO の補正(/hom)を確認するときは /hom の on と行列、/nn の "hom":1。PC の hom_check.py が同じ計算(点は results/hom_live_pts.json、基準の点は models/hom_ref_pts.json)
- iPhone 読み取りの結果確認は 06_phone_reader/results/<日付>/results.csv(見出し行が消えている場合あり)と保存画像。集計は summarize_phone.py
